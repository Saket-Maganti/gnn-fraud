# FraudShiftBench/TKDE and CoReGraph/ICLR differentiation

| Dimension | FraudShiftBench/TKDE | CoReGraph/ICLR |
|---|---|---|
| Primary question | Evaluation and claim validity under graph fraud protocol changes | Learning under unseen deployment-contract compositions |
| Contribution | Benchmark and evidence framework | Method, objectives, and theory |
| Main evidence | Protocol-sensitive benchmarking | Compositional routing generalisation |
| Theory | Evidence/support semantics | Fixed-mixture regret, composition, resource masks, selective risk |
| Main figures | Benchmark/evidence map | Router architecture, composition, resource interventions, new results |
| Shared data | Disclosed | Disclosed as inherited evaluation inputs |
| Shared text | Minimal and audited | Newly written method/theory narrative |
| Empirical claims | Frozen TKDE claims only | All Level-4 claims blocked pending new runs |

The 249-file FraudShiftBench scientific boundary is hash-frozen. CoReGraph code and paper cannot edit it. Sharing infrastructure does not turn prior benchmark results into evidence for the learned router. Any unavoidable overlap in definitions or dataset descriptions is disclosed and measured by `scripts/audit_cross_paper_overlap.py`; large phrase overlap fails without an explicit allowlist justification.
